# LIMO Pro VNC 双向复制粘贴排查记录

记录日期：2026 年 11 月 19 日。目标是在 Windows 和小车的 Ubuntu 桌面之间，通过 VNC 双向复制粘贴中文和英文文本。

**结果：已解决。** 在小车上并行运行支持剪贴板重定向的 TigerVNC 1.15.0 服务，Windows 改连 5901 端口后，用户确认复制粘贴可以使用。原有 5900 端口服务保留。

## 问题与环境

Windows 上的 TigerVNC Viewer 可以连接小车桌面，但双向复制粘贴，特别是中文文本，不能满足使用需求。此前曾尝试通过 SSH 脚本手动推送或拉取剪贴板，作为临时绕过办法；目标是恢复 VNC 内的自动同步。

| 项目 | 排查时的情况 |
| --- | --- |
| 小车系统 | Ubuntu 20.04.6 LTS，ARM64，用户 `agilex` |
| 小车图形桌面 | X11，显示 `:0` |
| Windows 客户端 | TigerVNC Viewer 1.16.0 |
| 原小车端服务 | `x0vncserver` 1.10.1，端口 5900 |
| 新小车端服务 | `x0vncserver` 1.15.0，端口 5901 |
| 排查时的小车地址 | `192.168.137.207`，可能随网络变化 |

## 排查与解决过程

1. **确认桌面和连接方式。** 小车使用 X11 图形会话，Windows 使用 TigerVNC Viewer。VNC 能显示桌面，并不代表两端的剪贴板同步功能一定兼容。
2. **核对版本和功能。** 发现小车的 `x0vncserver` 为 1.10.1，客户端为 1.16.0。TigerVNC 1.15.0 的发布说明提到为 `x0vncserver` 加入剪贴板重定向，因此将升级车端服务作为主要修复方向。发布说明：[TigerVNC 1.15.0](https://groups.google.com/g/tigervnc-announce/c/EfR0aDYeIwU)。
3. **在用户目录构建新版。** 从 Ubuntu 的软件源下载 TigerVNC 1.15.0 源码，在小车用户目录编译 ARM64 版本；构建所需的缺失开发文件也解压到用户目录。没有覆盖系统中的旧版服务。
4. **并行启动新服务。** 新版连接已有的 `:0` 桌面，监听 5901 端口，使用原有 VNC 密码文件。旧版 5900 服务继续运行，避免立即中断原连接。
5. **隔离测试中文。** 在小车上临时建立两个独立虚拟 X11 桌面，分别运行新版服务和测试客户端，验证“客户端 → 服务端”和“服务端 → 客户端”的中文文本都能传递。测试环境未使用当前桌面的剪贴板。
6. **实际客户端验证。** Windows 的 TigerVNC Viewer 改连 5901 后，用户确认复制粘贴可以使用。
7. **配置登录后启动。** 增加用户级启动脚本和图形桌面自启动项；小车的图形桌面登录后启动新版服务。启动脚本会先检查 5901 对应的服务是否已在运行，避免重复启动。

## 日常使用

1. 确认 Windows 与小车网络互通，且小车已登录图形桌面。
2. 打开 Windows 的 TigerVNC Viewer，在服务器地址栏输入：

   ```text
   192.168.137.207::5901
   ```

   `::5901` 表示指定 TCP 端口 5901；若小车地址变化，将前面的 IP 换成当前地址。输入原有 VNC 密码登录。
3. 在 Windows 与小车桌面之间复制、粘贴文本。普通编辑器一般使用 `Ctrl+C`、`Ctrl+V`；Linux 终端通常使用 `Ctrl+Shift+C`、`Ctrl+Shift+V`。

本次确认的是**文本**双向复制粘贴，包含中文；不能据此认为 VNC 支持直接复制文件。

## 车端文件和启动方式

| 用途 | 小车上的位置 |
| --- | --- |
| 新版服务程序 | `~/.local/src/tigervnc-1.15.0/build/unix/x0vncserver/x0vncserver` |
| 启动脚本 | `~/.local/bin/limo-vnc-clipboard-server` |
| 桌面自启动配置 | `~/.config/autostart/limo-vnc-clipboard.desktop` |
| 新服务日志 | `~/.local/src/tigervnc-1.15.0/vnc-5901.log` |
| VNC 密码文件 | `~/.vnc/passwd` |

新版服务为当前 `agilex` 的图形桌面提供访问，桌面登录后由自启动项启动；这不是开机前登录界面的远程访问服务。用户名目录、编译目录或桌面会话配置发生变化时，需重新检查启动脚本。

## 常用检查

通过 SSH 登录小车后，可以检查服务、端口和日志：

```bash
ssh LimoPro

# 查看新旧 VNC 服务进程
ps -ef | grep '[x]0vncserver'

# 查看端口是否监听
ss -ltn | grep -E ':5900 |:5901 '

# 查看新版服务日志
tail -n 80 ~/.local/src/tigervnc-1.15.0/vnc-5901.log

# 查看版本
~/.local/src/tigervnc-1.15.0/build/unix/x0vncserver/x0vncserver -version
```

如果重启后 5901 没有监听，先确认 `agilex` 已登录 X11 图形桌面、桌面自启动项仍存在，再检查日志。启动脚本需要能够访问该图形会话；从普通 SSH 会话直接运行时，可能缺少正确的 `DISPLAY` 或 `XAUTHORITY`，不应仅凭 SSH 登录成功就判断桌面已准备好。

如果连接后不能复制，先确认 Viewer 地址确实使用 `::5901`，再检查 Viewer 的剪贴板发送和接收设置，并分别测试两个方向的纯文本。若网络地址或 SSH 也有问题，可查看[网络故障排查与恢复](network-recovery.md)。

## 安全与限制

- 此次用户目录构建未启用 TLS，服务使用 VNC 密码认证，但 VNC 传输没有加密。只应在可信局域网内使用，不要直接暴露到公网；需要跨不可信网络访问时，应另行配置安全通道。
- 5900 仍是原有旧版服务；连接该端口不会自动获得本次 5901 的修复。
- 已设置登录后的自启动，但本记录中的自动启动配置尚未通过完整重启小车的实际测试验证。
