# 车端源码采集工具解析

本目录当前的可执行工具是 [export-vehicle-baseline.py](export-vehicle-baseline.py)。它将指定车端源码目录整理成压缩包，并为每个导出文件生成 SHA-256 校验值。`scripts/` 没有 `package.xml`，不是 ROS 包。

## 1. 它解决什么问题

车端 ROS 工作区含有厂商源码、本地修改、地图、第三方依赖和编译结果。直接复制整个工作区会混入大量生成文件；只从上游克隆又会漏掉车端已有修改。此脚本按固定范围读取工作目录中的实际文件，记录来源和 Git 状态，用于保存或比较一份核心代码基线。

它不修改车端源码、不启动节点、不编译，也不进行电脑与小车之间的双向同步。输出不包含所有系统依赖，不能替代完整设备备份。

## 2. 采集范围与路径映射

`SELECTIONS` 定义从 `--vehicle-home` 下读取哪些路径，默认从执行用户的主目录读取：

| 车端来源 | 归档中的位置 | 选择内容 |
| --- | --- | --- |
| `agilex_ws/src/limo_ros` | `ros1/src/limo_ros` | `limo_base`、`limo_bringup`、`learning_limo`，以及存在的顶层 LICENSE、README |
| `agilex_ws/src/agilex_pure_pursuit` | `ros1/src/agilex_pure_pursuit` | 包目录中的文件，应用排除规则 |
| `agilex_ws/src/set_nav_point` | `ros1/src/set_nav_point` | 同上 |
| `agilex_ws/src/fixed_point_navigation` | `ros1/src/fixed_point_navigation` | 同上 |
| `limo_ros2_ws/src/limo_ros2` | `ros2/src/limo_ros2` | `limo_base`、`limo_bringup`、`limo_msgs`，以及存在的顶层 LICENSE、README |

它按磁盘文件采集，而不是只导出 Git 已跟踪内容，因此也会纳入选择范围内的未提交修改与未跟踪文件。

## 3. 主流程与元数据

1. `argparse` 读取 `--vehicle-home` 和必填的 `--output`；输出文件已经存在时拒绝覆盖。
2. 为每个来源目录读取 Git HEAD 和 `git status --short`。不是 Git 仓库或 Git 命令失败时，相关值为 `null`；该状态记录描述来源仓库，可能包含此次未导出目录的变化。
3. 递归选择文件，排除指定目录和扩展名；发现符号链接时终止，要求人工检查。
4. 使用文件的实际字节生成归档成员和 SHA-256，记录文件大小及可执行标记。
5. `add_json()` 将采集时间、路径映射、来源状态和文件清单写入 `docs/04-源码与依赖/源码初始基线.json`。
6. 标准输出打印归档路径和导出文件数，便于后续传输和检查。

排除目录包括 `.git`、`build`、`devel`、`install`、`log`、`logs`、`Log` 和 `__pycache__`；排除扩展名包括 `.pyc`、`.pyo`、`.zip`、`.bag`、`.db3` 和 `.mcap`。这不是任意文件的敏感信息检测器，也没有穷举全部缓存或大数据格式；采集后仍应审核归档内容。

地图、参数以及选择范围内的图片等资源会保留。脚本不按“是否是文本源码”过滤全部文件，也不替你判断地图和旧示例是否应该继续使用。

## 4. 条件化使用示例

在具有这些工作区和 Python 3 的 Linux 设备上执行，例如：

```bash
python3 /path/to/export-vehicle-baseline.py \
  --vehicle-home /home/agilex \
  --output /tmp/limopro-capture-new.tar.gz
```

将 `/path/to/` 替换为脚本实际位置；输出路径每次应使用未存在的文件名，父目录需存在且可写。

生成后先查看归档成员，再解压到独立的比较目录。不要直接覆盖已经维护的源码或首次采集元数据；导出工具本身没有冲突合并和恢复功能。

## 5. 当前限制

- 来源路径、输出布局和选择范围硬编码在 `SELECTIONS`，不是通用 ROS 依赖分析器；新包不会自动加入。
- 来源根目录不存在时会报错，但列表中单个成员不存在时会跳过。因此需要核对归档清单，不能只凭命令退出成功判断所有预期内容都在。
- 它不会锁住正在编辑的工作区；文件读取和 Git 状态不是原子快照，采集时应避免并发修改。
- 失败后可能留下部分输出归档，脚本没有事务性清理；再次运行要使用新路径或先人工确认失败文件。
- 缺失的许可证、外部源码修改、系统软件包和设备配置不会由此工具自动补齐。

建议阅读顺序：先看 `SELECTIONS` 与排除规则，再看 `main()` 中逐文件归档，最后看 `git_output()` 和 `add_json()`。本说明根据静态代码编写，文档任务中没有重新对车端执行采集。
