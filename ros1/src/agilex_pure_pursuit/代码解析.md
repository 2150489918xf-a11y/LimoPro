# agilex_pure_pursuit 代码解析

> 分析日期：2026-11-24。本文依据当前包的源码、构建文件、启动文件和参数文件进行静态分析，未编译，未启动节点，未做实车验证。原 [README](README.md) 中“仅在四轮差速模式下测试过”是原作者的说明，不是本次验证结果。

## 1. 包的职责和边界

真实 ROS 包名与 CMake 工程名均为 `agilex_pure_pursuit`。包内实现两个相互独立的节点：

- `record_path`：从 TF 读取机器人在 `map` 坐标系下的位置，将行驶轨迹暂存在内存中，退出时写入文本文件。
- `pure_pursuit`：启动时读取文本轨迹，根据 TF 位姿选择前视点，直接发布速度，循环跟随轨迹。

这里实现的是一个差速运动学路径跟随演示。没有 `move_base` action 客户端，没有全局规划器、代价地图或绕障重规划。激光处理的作用是满足条件时将速度置零。

在标准 catkin devel 空间中，成功构建后的可执行文件通常位于 `devel/lib/agilex_pure_pursuit/`。仅使用 install 空间时，虽然 `record_path.launch` 已安装，但它引用的 `record_path` 可执行文件不会由当前安装规则一起提供。

构建依赖的实际情况：

- CMake 查找 `roscpp`、`tf`、`sensor_msgs`、`geometry_msgs`、`nav_msgs` 和 Eigen3；Eigen 头文件路径还硬编码为 `/usr/include/eigen3`。

- `catkin_package()` 没有导出库、头文件目录或依赖列表。
- `set(CMAKE_CXX_FLAGS "-std=c++11 -o3")` 中的 **`-o3` 是小写字母 o**，表示输出文件选项，不是优化选项 `-O3`。它可能干扰构建，应检查实际编译命令；本文没有修改它。
- 源码使用 `geometry_msgs::Twist`、`std::stringstream`、`std::numeric_limits` 等符号，没有在使用文件中全部直接包含对应头文件，部分依赖间接包含，需实际编译确认兼容性。

因此，本文列出的目标是“构建文件已声明的目标”，不代表当前快照已成功编译。

## 4. 录制轨迹：record_path.cpp

### 4.1 数据流程

```text
TF: map ← base_link
    ↓ 以 20 Hz 尝试读取最新变换
与上次采样位置比较，平面距离严格大于 0.05 m
    ↓
追加到内存中的 nav_msgs/Path，并发布 target_path
    ↓ ROS 主循环正常结束
覆盖写入文本轨迹文件
```

`lookupTransform("map", "base_link", ...)` 得到 `base_link` 在 `map` 中的位姿。TF 监听器负责接收变换；这里没有订阅一个名为 `pose` 的定位话题。

采样细节：

- 第一次循环把当时的位置保存为距离比较基准，**不会立即把起始位置加入轨迹**。
- 之后只在相对上一次采样平移超过 `0.05 m` 时记点，原地旋转不会记录新点。
- 每个点只填写位置和 header，没有填写有效姿态四元数；跟随器随后会用相邻位置重新估计航向。
- 每次发布的是从录制开始累计到当前的完整路径；发布器队列为 1，并启用 latch。

### 4.2 路径、格式与保存时机

[record_path.cpp](src/record_path.cpp) 的私有参数 `~path_file` 默认值为：

```text
/home/agilex/target_path.txt
```

[record_path.launch](launch/record_path.launch) 也将 `~path_file` 设置为这个绝对路径。文件每行只有两个以空格分隔的数，单位为米：

```text
1.02 0.31
1.08 0.32
1.15 0.34
```

文件没有表头、时间戳、航向或坐标系字段，坐标系由代码约定为 `map`。代码没有设置输出数值精度，使用 C++ 流的默认格式。

**循环运行期间不写文件。** 正常 Ctrl+C 触发 ROS 退出、循环结束后，才创建 `ofstream` 并覆盖写入。强制结束进程、断电等情况不会保证轨迹落盘；空轨迹也可能覆盖旧文件。代码没有检查文件打开或写入是否成功。

## 5. 路径结构与搜索：path.h / path.cpp

`WayPoint` 保存 `id`、二维 `position` 和 `heading`。`Path::push_back()` 自动设置从 0 开始的连续编号，同时保存每对相邻点的欧氏距离。

- `makePath()`：对文件中的每一对相邻点，使用 `atan2(y[i+1]-y[i], x[i+1]-x[i])` 计算该点的路径切线方向；最后一点继承前一点的航向。
- `findClosestPoint(pose, start_id)`：从上次最近点编号开始向前搜索，候选下标满足 `start_id <= i < min(start_id + 10, N - 1)`。最多比较 10 个点，不回头，不做整条路径的最近点搜索，并且不包含最后一点。
- `findNextPoint(closest, distance)`：从最近点开始累计轨迹段长，返回累计长度第一次大于等于 `distance` 时的下一顶点；剩余长度不足时返回终点。它沿折线查找，**不对前视点插值**。
- `getStartPoint()`、`getEndPoint()` 直接访问首尾元素，没有空路径保护。

## 6. 跟随节点的初始化和状态机

[pure_pursuit.cpp](src/pure_pursuit.cpp) 构造函数读取参数、创建发布和订阅，然后**固定读取** `/home/agilex/target_path.txt`。这个文件路径没有读取 `~path_file`，修改录制节点的输出路径不会自动修改跟随器的输入路径。

载入成功后生成内部 `Path`，发布可视化轨迹，并进入 `START`；打开文件失败则保持 `IDLE`。文件只在构造时读取一次，没有文件变化检测或在线路径更新订阅。

`run()` 的顺序为 `track()` → `rate.sleep()` → `ros::spinOnce()`，标称频率 `50 Hz`，TF 等待会降低实际频率。

| 状态 | 实际行为 | 转移条件 |
| --- | --- | --- |
| `IDLE` | 取得 TF 后保持本轮速度为零 | 没有在线加载路径、离开 IDLE 的外部接口 |
| `START` | 原地对齐第一条路径段的航向，线速度保持 0 | 航向误差连续 11 次小于阈值后进入 TRACK |
| `TRACK` | 搜索最近点、前视点，计算并发布速度 | 前视点编号到达末点时，下轮将搜索基准和目标重置为起点 |

需要区分“循环跟随”和“实际到达终点”：代码只判断 `next_waypoint.id` 是否为末点，**没有判断机器人已到达末点**。前视点一旦选到末点，下一控制轮就以起点为目标；随后再从起点附近重新搜索。没有停止状态、单次运行模式或反向沿原路径行驶的模式。

`START` 只调整朝向，不会先规划移动到起点。启动位置必须与录制路径有合理关系；任意位置启动时，这段逻辑不能保证先回到起点。

## 7. 控制公式和障碍判定

设机器人在 `map` 下的位置为 `(x, y)`，朝向为 `θ`，前视点为 `(x_t, y_t)`。`calculateVel()` 将目标转换到车体平面：

```text
dx =  cos(θ) × (x_t - x) + sin(θ) × (y_t - y)
dy = -sin(θ) × (x_t - x) + cos(θ) × (y_t - y)
ds = sqrt(dx² + dy²)
```

在不触发障碍停车的情况下：

```text
v = max_lin_vel
若 |dy| < 0.001：ω = 0
否则：ρ = ds² / (2 × dy)，ω = v / ρ = 2 × v × dy / ds²
若最近点与前视点的航向差绝对值 < 0.001 rad：ω = angle_kp × ω
最后把 ω 限制到 [-max_ang_vel, max_ang_vel]
```

`look_ahead_dist` 决定沿路径向前搜索多远，真正参与曲率公式的是机器人到选中点的 `ds`，两者不一定相等。线速度没有按曲率、距离或终点误差减速，也没有倒车分支；`dy` 决定转向方向。

`START` 下采用航向比例控制：

```text
eθ = normalizeAngle(起点航向 - 当前航向)
ω = clamp(angle_kp × eθ, -max_ang_vel, max_ang_vel)
v = 0
```

`normalizeAngle()` 当前两个 while 的执行顺序把误差折回 `(-π, π]`，恰为 `-π` 时最终会返回 `+π`。`checkHeading()` 要求连续 11 次满足角度阈值；以无阻塞的 50 Hz 估算约为 0.22 秒。

`checkPosition()` 计算的是位置误差在车体前向轴上的投影，并进行连续计数，**但没有任何调用点**，不参与到点判断或终点停车。`position_kp` 也未参与控制。

激光检查由 `scanCallback()` → `detectOobstacle()` 完成：

1. 将每个量测按 `scan.angle_min + i × scan.angle_increment` 转换为平面 `(x_s, y_s)`。
2. 在 `x_s > 0` 且 `|y_s| < obstacle_check_y_range` 的前方条带内，取最小 `x_s` 作为 `obstacle_distance_`。
3. 跟随阶段满足 `obstacle_distance_ < dx` 且 `obstacle_distance_ < obstacle_check_x_range` 时，同时令 `v = 0`、`ω = 0`。

这相当于前方条带内的停车检查，没有绕障规划；`START` 的原地转向不调用这个停车判断。量测直接在激光坐标下计算，没有根据 `scan.header.frame_id` 转换到 `base_link`，因此传感器位置和朝向会影响判定。

## 10. 启动前提与可用入口

运行前需要 ROS 1/catkin 环境、编译依赖、可用的 ROS master，以及稳定的 `map` 到 `base_link` TF。该 TF 通常由外部定位或建图系统和底盘里程计共同提供；本包不会启动这些系统。

跟随还需要至少两个有效轨迹点、与录制坐标系一致的定位、激光数据，以及订阅速度的底盘或仿真。两个 launch 都只启动本包自己的节点，不负责底盘、雷达或定位。原作者仅声明四轮差速模式测试经历，不能据此认定适配阿克曼转向、其他模式或任意车型。

在处理构建问题、成功编译并 `source <工作区>/devel/setup.bash` 后，构建文件支持以下入口；这些是说明用命令，本文未执行：

```bash
# 录制：在正常退出时保存轨迹
roslaunch agilex_pure_pursuit record_path.launch

# 跟随：将控制输出先重映射到观察话题，不直接发布实际 /cmd_vel
rosrun agilex_pure_pursuit pure_pursuit _cmd_vel_topic:=/pure_pursuit_debug_cmd
```

第二条没有加载 YAML，因此采用源码默认值。若使用 `pure_pursuit.launch`，会加载 YAML 并默认直接向 `cmd_vel` 输出。录制 launch 的文件参数是节点内部固定配置，不是已声明的 launch arg。

录制与跟随宜分阶段运行：先结束录制、确认文件已写入，再启动跟随。两个节点都能发布 `target_path`，同时运行会使可视化看到不同来源的轨迹。

## 11. 代码可证的问题与调试检查

| 问题 | 源码依据 | 影响或检查方向 |
| --- | --- | --- |
| 空文件、单点和坏行未验证 | `loadTargetPath()` 不检查 `ss >> x >> y` 的结果，打开成功就返回 true；`makePath()` 无条件读取末点和内部末航向 | 空文件或单点路径存在越界访问，坏行可能使用未初始化数值；先逐行检查并保证至少两点 |
| 最近点搜索边界不完整 | `findClosestPoint()` 使用严格小于上界，默认构造 `WayPoint` 不初始化成员 | 末点不参与最近搜索，搜索区间为空时可能返回无效对象 |
| TF 异常仍被录制器继续处理 | `record_path` 捕获异常后没有 `continue` | 后续可能使用旧变换；首次就失败时不能保证是有效位姿 |
| TF 丢失时不主动发停车命令 | `track()` 在 `getPose()` 失败后直接返回 | 上次速度是否持续取决于底盘超时机制，本包没有兜底停车 |
| 激光首帧前和断流没有保护 | `obstacle_distance_` 没有初始化，只有扫描回调更新，也没有时间戳超时检查 | 首帧前可能读取未初始化值，断流后继续使用旧值 |
| 激光有效性检查不完整 | 只显式排除小于 `range_min` 的值，没有统一过滤非有限值和大于 `range_max` 的值 | 应对照实际雷达量测格式检查停车行为 |
| 前视点可视化存在未初始化路径 | `track()` 的静态 `WayPoint` 默认未初始化，START 尚未对齐或 IDLE 时仍发布它 | `/next_waypoint` 不一定从启动起就是有效姿态 |
| 无终点距离判定和减速 | TRACK 检查前视点 id，速度设为 `max_lin_vel` | 不能把它当作到点后停车的任务执行器 |
| 退出没有最终零速度 | 主循环和析构没有专门发布停车指令 | 需要确认下游控制器的速度超时机制 |
| 多个速度发布源无仲裁 | 直接发布 `cmd_vel` | 与 `move_base`、遥控或学习例程同时运行时可能竞争 |

建议按以下顺序定位问题，命令只用于检查，本文未执行：

```bash
rospack find agilex_pure_pursuit
rosrun tf tf_echo map base_link
rostopic hz /scan
rostopic info /cmd_vel
rosparam get /pure_pursuit
wc -l /home/agilex/target_path.txt
```
