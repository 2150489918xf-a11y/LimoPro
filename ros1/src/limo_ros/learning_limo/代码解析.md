# learning_limo 代码解析

> 分析日期：2026-11-24。已读取本包 `package.xml`、`CMakeLists.txt` 和全部两个 `.cpp` 文件。当前包没有 `.h`、`.py`、`.launch`、`.yaml` 或自定义 `.msg` 文件。本文仅做静态分析，未编译、未启动节点、未做实车验证。

## 1. 职责与真实包名

[package.xml](package.xml) 和 [CMakeLists.txt](CMakeLists.txt) 的真实包名/工程名均为 `learning_limo`。这是 ROS 1 发布订阅教学示例，用来理解 `geometry_msgs/Twist` 速度消息：

- `talker`：以标称 10 Hz 发送 10 次固定速度消息，然后退出。
- `listener`：持续订阅速度消息，打印 `linear.x`、`linear.y`、`angular.z`。

**本例不是发布 `std_msgs/String` 的 chatter 示例。** 虽然源码保留了 `chatter_pub`、`chatterCallback` 等变量名、`std_msgs/String.h` 头文件和旧注释，真正的话题是 `cmd_vel`，消息类型是 `geometry_msgs/Twist`。

本包不负责底盘协议、串口、里程计、定位、导航或运动闭环。`listener` 只输出日志，不会执行速度控制。

## 3. 构建与安装：声明了目标不等于当前能构建

### 3.1 依赖和已启用的目标

CMake 查找 `geometry_msgs`、`roscpp`、`rospy`、`std_msgs`、`message_generation`。清单使用 package format 1 的 `<build_depend>` / `<run_depend>`，包含上述常规依赖，并声明 `message_runtime` 的运行依赖。

`catkin_package()` 导出 `geometry_msgs roscpp rospy std_msgs message_runtime`；`include_directories()` 包含 `include` 和 `${catkin_INCLUDE_DIRS}`，当前包没有实际提供的自定义头文件。

| 已声明的 C++ 目标 | 源码 | 链接 | 标准 devel 输出位置（构建成功后） |
| --- | --- | --- | --- |
| `talker` | `src/talker.cpp` | `${catkin_LIBRARIES}` | `devel/lib/learning_limo/talker` |
| `listener` | `src/listener.cpp` | `${catkin_LIBRARIES}` | `devel/lib/learning_limo/listener` |

本包没有自定义库、Python 安装程序、launch 或参数文件。安装部分全部是模板注释，因此这两个可执行文件没有实际 `install(TARGETS ...)` 规则，不能假定仅加载 install 环境也能找到它们。

### 3.2 消息生成依赖存在问题

[CMakeLists.txt](CMakeLists.txt) 的实际代码为：

```cmake
add_executable(talker src/talker.cpp)
target_link_libraries(talker ${catkin_LIBRARIES})
add_dependencies(talker ${PROJECT_NAME}_generate_messages_cpp)

add_executable(listener src/listener.cpp)
target_link_libraries(listener ${catkin_LIBRARIES})
add_dependencies(talker ${PROJECT_NAME}_generate_messages_cpp)
```

需要注意：

1. 两条依赖都加给了 `talker`，第二条并没有为 `listener` 添加依赖。
2. `${PROJECT_NAME}_generate_messages_cpp` 展开为 `learning_limo_generate_messages_cpp`。
3. 当前包没有 `.msg` 文件，`add_message_files()` 和 `generate_messages()` 都被注释，没有创建该生成目标的逻辑。
4. `find_package(... message_generation)` 只查找工具，不会自动为这个包创建上述消息生成目标。

所以按当前包内配置，依赖目标没有定义来源，在标准 catkin 构建配置/生成阶段可能报“依赖目标不存在”。仅重复编译或安装 `message_generation` 不能替代对这段配置的检查。本文没有修改构建文件，也没有实际验证构建报错。

两个源文件只使用已有的 `geometry_msgs` 消息，不能因为 CMake 有这些遗留配置就认为包实现了自定义消息。

## 4. talker.cpp：消息如何发出

[talker.cpp](src/talker.cpp) 的流程是：

```text
ros::init(..., "talker")
    ↓
创建公共 NodeHandle
    ↓
advertise<geometry_msgs::Twist>("cmd_vel", 1000)
    ↓
for count = 0 到 9：
    创建 Twist → 设置各分量 → publish → spinOnce → 按 10 Hz sleep
    ↓
直接返回，退出进程
```

每次发送的消息内容完全相同：

| 字段 | 值 | 常用物理含义 |
| --- | --- | --- |
| `linear.x` | 0.1 | 车体前向速度，m/s |
| `linear.y` | 0 | 侧向速度，m/s |
| `linear.z` | 0 | 竖向速度，m/s |
| `angular.x` | 0 | 绕 X 轴角速度，rad/s |
| `angular.y` | 0 | 绕 Y 轴角速度，rad/s |
| `angular.z` | 0 | 平面转向角速度，rad/s |

发布器队列为 1000，没有启用 latch。`ros::Rate(10)` 和 10 次循环对应约 1 秒的标称发布过程；这不是基于实际位移或时间反馈的直线行驶算法。

程序没有等待订阅者连接，第一条消息可能在 TCPROS 连接建立前就已发出。总共调用 10 次 `publish()`，不代表任何订阅者都保证收到 10 条。进程运行时间很短，也会影响观察和频率统计。

循环条件只有 `count < 10`，没有 `ros::ok()`。`spinOnce()` 允许处理回调，但这里没有注册业务订阅或定时回调。最后一次消息仍是 `linear.x = 0.1`，**退出前没有主动发送零速度**；机器人是否停下取决于底盘控制器的超时和其他控制源，不能从本包保证。

## 5. listener.cpp：消息如何接收

[listener.cpp](src/listener.cpp) 初始化名为 `listener` 的节点，订阅相对话题 `cmd_vel`，队列为 1000，随后使用 `ros::spin()` 持续等待回调。

`chatterCallback()` 的参数为 `geometry_msgs::TwistConstPtr`，每收到一条消息执行：

```text
x = msg->linear.x
y = msg->linear.y
z = msg->angular.z
    ↓
分别打印 I get x / I get y / I get z
```

日志变量 `z` 代表的是**绕 Z 轴的角速度**，不是 `linear.z`。一条速度消息会产生三条 INFO 日志。若系统还有其他节点发布同一话题，listener 也会接收这些消息，它没有按发布者筛选，更不负责判断哪个命令生效。

## 6. Topic、参数与其他接口

| 节点 | 方向 | 源码话题名 | 无命名空间时 | 类型 | 队列 |
| --- | --- | --- | --- | --- | --- |
| `talker` | 发布 | `cmd_vel` | `/cmd_vel` | `geometry_msgs/Twist` | 1000 |
| `listener` | 订阅 | `cmd_vel` | `/cmd_vel` | `geometry_msgs/Twist` | 1000 |

消息本身没有 header，也没有坐标系字段；由速度控制系统约定车体坐标语义。普通 ROS 名称重映射可改变话题名。

代码没有参数读取。速度 `0.1`、标称频率 `10 Hz`、次数 `10` 和队列大小 `1000` 全是源码常量，不能通过 `_speed:=...` 等未实现的私有参数改变。

本包没有 action、service、TF 查询、文件读写或硬件设备接口。`std_msgs/String.h` 和 talker 中的 `<sstream>` 等头文件属于未使用的遗留内容，不代表存在字符串消息通道。

## 7. 启动前提与隔离学习方法

学习发布订阅本身只需要 ROS 1、相关消息和 `roscpp` 依赖、ROS master，以及处理构建依赖问题后成功编译的两个目标；不需要启动真实底盘或导航。

先解决并验证本包的 CMake 消息生成依赖，成功构建后加载相应 `<工作区>/devel/setup.bash`。此后两个已声明的 C++ 目标才对应以下运行示例。本文未执行这些命令：

```bash
# 终端 1：先开始监听，统一重映射到独立的教学话题
rosrun learning_limo listener cmd_vel:=/learning_cmd_vel

# 终端 2：再启动短时发布器，使用同一重映射
rosrun learning_limo talker cmd_vel:=/learning_cmd_vel
```

这样观察的是 `/learning_cmd_vel`；两边必须重映射到相同名称。直接运行而不重映射时，talker 会向实际 `cmd_vel` 发布非零速度，有底盘订阅时可能造成运动。

不要把上面的命令理解为当前仓库已经构建成功，或这两个目标已经安装到 install 空间；本文仅说明已声明目标在成功构建后的使用关系。

## 8. 代码可证的问题与调试建议

| 问题/容易误读处 | 证据 | 建议检查 |
| --- | --- | --- |
| 消息生成依赖目标无定义 | 无消息定义和 `generate_messages()`，却引用 `learning_limo_generate_messages_cpp` | 先检查 CMake 配置日志，不要只检查 CPP |
| listener 的依赖配置疑似复制错误 | 第二条 `add_dependencies()` 仍指向 talker | 区分“目标声明存在”和“依赖关系正确” |
| 教学注释仍写 chatter | advertise/subscribe 实际用 `cmd_vel` 与 Twist | 以代码和 `rostopic type` 为准 |
| 最初消息可能收不到 | 发布后没有等待连接，程序约 1 秒即退出 | 先启动 listener 或 echo 再启动 talker |
| 退出不主动停车 | 没有最后一条零速度，也无 shutdown hook | 学习时使用独立话题，实际控制需另核底盘超时机制 |
| 多个发布者可能竞争 | topic 没有仲裁，listener 不区分来源 | 用 `rostopic info` 查看所有发布者 |
| 日志 z 语义易误解 | 回调读取的是 `angular.z` | 按 rad/s 的角速度理解 |
| 没有安装规则 | install 段全部被注释 | 确认 source 的是哪个工作区以及是否有对应产物 |

可使用以下只读检查；这些也未在本次执行：

```bash
rospack find learning_limo
rostopic type /learning_cmd_vel
rostopic info /learning_cmd_vel
rostopic echo /learning_cmd_vel
```

没有启动发布器时，话题类型可能尚不可查询。调试短时发布器宜先启动 listener/echo，再启动 talker；`rostopic hz` 的样本窗口只有约一秒，不能仅凭样本很少就认定循环频率错误。若完全没有消息，依次核对 ROS master、包解析路径、构建结果、环境加载、消息类型和两端 remap。
