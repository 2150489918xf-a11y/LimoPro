# limo_msgs 代码解析（ROS 2 Foxy）

本包定义车辆状态消息 `limo_msgs/msg/LimoStatus`。它是接口包：没有节点、不打开串口、不主动发布话题，也没有 launch 文件。底盘驱动依赖本包生成的类型来发布 `/limo_status`。

分析日期：2026-11-24。本文依据 [消息定义](msg/LimoStatus.msg)、[CMakeLists.txt](CMakeLists.txt)、[package.xml](package.xml) 以及相邻底盘驱动的赋值逻辑编写，属于静态分析，未在本次文档编写中构建或订阅实车数据。

## 1. 文件与生成流程

| 文件 | 职责 |
| --- | --- |
| [msg/LimoStatus.msg](msg/LimoStatus.msg) | 状态消息字段的唯一接口定义 |
| [CMakeLists.txt](CMakeLists.txt) | 调用 `rosidl_generate_interfaces` 生成接口，并导出运行时依赖 |
| [package.xml](package.xml) | 声明 `ament_cmake`、`std_msgs`、生成器和消息运行时依赖；标记为 `rosidl_interface_packages` |

构建时，ROSIDL 根据 `.msg` 生成相应语言的接口，例如 C++ 头文件 `limo_msgs/msg/limo_status.hpp`。这些生成文件位于构建和安装目录中，不应手工改写后当作源接口维护。

依赖关系为：

```text
LimoStatus.msg → ROSIDL 生成代码 → limo_base 发布 → 状态监控/网页后端等订阅
```

消息字段只描述数据结构，不包含底盘协议的解析。要理解值来自哪里，应查看 [limo_base/src/limo_driver.cpp](../limo_base/src/limo_driver.cpp) 中 `parseFrame()` 的 `MSG_SYSTEM_STATE_ID` 分支和 `publishLimoState()`。

## 2. 每个字段的含义

| 字段 | 类型 | 当前驱动中的来源或用途 |
| --- | --- | --- |
| `header` | `std_msgs/Header` | 发布状态的时间信息；当前驱动只写时间戳，未设置 `frame_id` |
| `vehicle_state` | `uint8` | 系统状态帧的第 0 数据字节，原始车辆状态编号 |
| `control_mode` | `uint8` | 系统状态帧的第 1 数据字节，原始控制模式编号 |
| `battery_voltage` | `float64` | 第 2、3 字节按高字节在前组合，再乘 `0.1`，表示电池电压 |
| `error_code` | `uint16` | 第 4、5 字节组合的故障位掩码；可能同时存在多个故障 |
| `motion_mode` | `uint8` | 一般来自系统帧第 6 字节；驱动强制麦克纳姆模式时使用驱动中的模式值 |

`.msg` 没有定义枚举常量，因此编号含义还需要与当前底盘协议和驱动对照。仓库的 [limo_protocol.h](../limo_base/include/limo_base/limo_protocol.h) 定义：四轮差速 `0x00`、阿克曼 `0x01`、麦克纳姆 `0x02`、未知 `0xff`。`vehicle_state` 和 `control_mode` 的完整取值表不能仅凭本消息定义补齐。

`error_code` 应按位判断，不宜把它作为只有一个取值的枚举。当前驱动的 `processErrorCode()` 检查 `0x0001`、`0x0002` 的低电压提示，`0x0004` 的遥控连接提示，`0x0008` 到 `0x0040` 的四个电机驱动提示，以及 `0x0100` 的驱动状态提示；这里描述的是代码中的解释，硬件协议仍需核对。

## 3. 构建和使用

在依赖准备好的 ROS 2 Foxy 环境中，于仓库 `ros2/` 目录执行：

```bash
source /opt/ros/foxy/setup.bash
colcon build --packages-select limo_msgs
source install/setup.bash
ros2 interface show limo_msgs/msg/LimoStatus
```

上面的命令生成和检查接口，不启动底盘。实车驱动已运行且当前终端加载同一 ROS 域和工作区时，才可以检查：

```bash
ros2 topic type /limo_status
ros2 topic info /limo_status -v
ros2 topic echo /limo_status
```

其他 C++ 包使用本接口时，应声明 `limo_msgs` 依赖并包含生成的 `limo_msgs/msg/limo_status.hpp`；Python 使用 `from limo_msgs.msg import LimoStatus`。实际订阅器由使用它的包实现，本包不提供默认订阅程序。

## 4. 与 ROS 1 的区别

ROS 1 的对应定义位于 [limo_base/msg/LimoStatus.msg](../../../../ros1/src/limo_ros/limo_base/msg/LimoStatus.msg)，类型名为 `limo_base/LimoStatus`。ROS 2 把接口拆为独立的 `limo_msgs` 包，类型名为 `limo_msgs/msg/LimoStatus`。

字段相似不代表两种消息能够跨 ROS 版本直接通信；跨版本传递仍需要合适的桥接和类型映射。调整消息字段时，也需要同时考虑发布者、订阅者和可能的桥接端。

## 5. 维护和验证关注点

- `CMakeLists.txt` 显式查找和引用 `builtin_interfaces`，但 `package.xml` 没有相应的显式声明。现有系统的传递依赖可能掩盖此问题，应在依赖整理时核对。
- 当前驱动 `publishLimoState()` 中的 `rclcpp::Time(stamp)` 与其输入秒值不一致，可能让 `header.stamp` 失真；问题位于驱动，不能通过修改消息类型解决。
- 电压是电压值，不是电池百分比；网页展示百分比需要额外的电池模型或标定。
- 修改 `.msg` 后，需要重新构建本包及使用新接口的相关包，重新加载环境并重启相关进程，避免旧生成类型和新定义混用。

推荐阅读顺序：先看字段定义，再看 ROSIDL 构建，再顺着驱动的系统状态解析理解数据来源。更完整的驱动说明见 [limo_base 解析](../limo_base/代码解析.md)。
